AlgorithmicNLA.AlgorithmicNLA — Module
AlgorithmicNLA

Numerical linear algebra algorithms written against the AbstractArray interface so that they run on any array backend supporting a small set of vectorized primitives.

The package is organized as a set of algorithm files, each implementing one factorization or decomposition, included below.

Arrays and utilities

AlgorithmicNLA.NLAArray — Type
NLAArray(A::AbstractArray)

Wrap A without copying or changing its element type to select AlgorithmicNLA methods through the standard array and LinearAlgebra interfaces. parent(A) on the wrapper returns the underlying storage.

Copies, views, reshapes, broadcasts, and array-valued reductions preserve the wrapper. Scalar indexing obeys the parent's indexing policy. Backend adaptation uses Adapt.adapt and preserves the wrapper.

LU selects this package's portable implementation; QR currently delegates to the parent backend. QR delegation preserves backend errors and rejects a change to floating-point factor storage precision.

AlgorithmicNLA.lu! — Method
AlgorithmicNLA.lu!(A, pivot=RowMaximum(); check=true, allowsingular=false, blocksize=64)

Compute AlgorithmicNLA.lu in place, overwriting A with packed factors. The returned factor storage aliases A. Pivot and status arrays are allocated on the same backend. blocksize must be a positive integer.

AlgorithmicNLA.lu — Method
AlgorithmicNLA.lu(A, pivot=RowMaximum(); check=true, allowsingular=false, blocksize=64)

Compute a dense LU factorization with F.L * F.U == A[F.p, :], using a copy of A. Return a standard LinearAlgebra.LU with NLAArray factors and pivots stored on the input backend. Floating-point factor storage retains the input element type; integer input uses Julia's allocating LU element type.

The blocked driver and recursive panels follow LAPACK 3.12.1 GETRF/GETRF2. RowMaximum uses absolute value for real entries and abs(real)+abs(imag) for complex entries, with first-index tie breaking. NoPivot and RowNonZero are also supported. check=true rejects nonfinite inputs and throws for singular factors unless allowsingular=true; a zero pivot with NoPivot still throws.

Array primitives keep pivots on device; checking input finiteness and reading the final status synchronize. Backend matrix products determine their internal compute precision. No custom GPU kernels or implicit factor promotion are used. Complex division follows LAPACK LADIV in at least Float32 arithmetic, rounding back to the storage type. This avoids Float64 intermediates for ComplexF32 on Metal and overflow/underflow in a naive reciprocal.

AlgorithmicNLA.realtype — Method
realtype(T)

The real floating point type used for magnitudes of elements of type T, i.e. real(float(T)). Used for norms, tolerances, and singular values.

AlgorithmicNLA.unit_roundoff — Method
unit_roundoff(T)

The unit roundoff u = eps(realtype(T)) / 2 of the floating point type associated with T.
